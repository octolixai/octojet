# GB10 results, 2026-09-28

Box: one DGX Spark-class GB10 system, 128 GB unified memory. Model: Qwen3.8 Flash Next. Engines:
- vLLM with a mixed NVFP4/FP8 checkpoint (139 GB on disk), MTP with 2 speculative tokens;
- TensorFold 0.3.6.2 in `nvcr.io/nvidia/pytorch:26.07-py3`, with turboderp's EXL3 3.05 bpw pack (80 GB) or
  Vontra's MLX 4-bit MTP checkpoint (106 GB).

## Accuracy (`bench/acc_eval.py`, greedy, thinking off)

GSM8K: first 250 test questions. HumanEval: all 164, executed with no network.

| Engine + weights | GSM8K | HumanEval |
|---|---:|---:|
| vLLM + NVFP4 | 0.968 | 0.945 (155/164) |
| TensorFold + EXL3 3.05 bpw | 0.972 | 0.957 (157/164) |
| TensorFold + MLX 4-bit | 0.976 | 0.939 (154/164) |

Paired on GSM8K, vLLM vs EXL3: 3 questions right only on vLLM, 4 right only on TensorFold. No detectable
difference. vLLM vs MLX 4-bit: 2 right only on vLLM, 4 right only on MLX. 95% intervals are about ±2-3 points (GSM8K) and ±3-4 points (HumanEval).

## Agent-shaped latency (`bench/agent_bench.py`)

A 110k-token conversation (cold), then three follow-up turns each adding ~7k new tokens and asking for ~600
tokens. Streaming; time to first token includes prompt processing and prefix reuse.

| Engine + weights | Turn | Prompt tokens | TTFT | Decode tok/s | Total |
|---|---|---:|---:|---:|---:|
| TensorFold EXL3 | cold | 110,151 | 148.1 s | 40.2 | 161.6 s |
| | +1 | 117,371 | 10.3 s | 50.6 | 22.1 s |
| | +2 | 124,637 | 10.5 s | 70.4 | 18.4 s |
| | +3 | 131,856 | 16.4 s | 64.4 | 25.0 s |
| TensorFold MLX 4-bit | cold | 110,151 | 54.9 s | 37.4 | 70.5 s |

TensorFold with the MLX checkpoint allocated a 154,690-token window on this box (87.1 GiB startup estimate);
with EXL3 it allocated the full 262,144.

A separate single 62k-token prompt on TensorFold EXL3 took 85.4 s end to end, with the right answer.

## M0 reading (internal agent brief)

vLLM's NVFP4 prompt processing on this box matches TensorFold's MLX 4-bit path: 52.7 s vs 54.9 s cold for
110k tokens (~2,090 vs ~2,010 tok/s), 5.1-6.2 s vs 4.3-5.9 s for follow-ups. No NVFP4 prefill advantage is visible
through vLLM. Whether that's the format or vLLM's sm_121 kernels is what M1 (a standalone FP4 MMA
microbenchmark) would decide. Per agent step, TensorFold + MLX 4-bit is fastest (12-15 s vs vLLM's 19-28 s),
mostly from decode (57-79 vs 30-46 tok/s).
